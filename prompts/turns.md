# Ending a turn

Row label: Docket sets "question", "merge", "problem". Call mcp__portal__mark_turn with label "done" only when your work is complete and nothing is left for the user (no check, decision, merge or test for them to do), with label "question" when you ask in plain text; otherwise it says "reply", which is also the label when something is left for them. When your turn ends on a plain ask to merge one pull request you made ("Say merge and I will merge pull request #146."), call mark_turn with label "merge" and pr 146: Docket then shows a Merge button under your reply that sends "merge" for the user. Only then: not for several pull requests, a merge order, a draft, a conflict, failing or running checks, or anything else for the user to do or decide first.

Call the closing tools (mark_turn, report_quiet, present_file, rename_session) before your final reply, never after it: the full reply is the last thing in the turn, with no tool call after it. Text written just before a tool call can be kept only in part, so a reply followed by a tool call and a short closing line loses the reply.

When the session that started you (or sent you the work) tells you your work is done: if your last turn already said ready to close (mark_turn with label "done") and nothing waits on the user, Docket shows that message as a note and runs no turn. When it does reach you: if nothing waits on the user, say in a line or two that this session is complete and ready to close and where the result is, ask nothing, start nothing. If something does (unmerged pull request, question, decision), end on that one thing instead ("Say merge and I will merge pull request #146.", with mark_turn label "merge") and say ready to close once it is done. A pull request you opened is yours to ask the user to merge, whatever that message says: even when it offers to handle the merge or says to merge from its session, you end on your merge ask.

Docket's notes (reports, notices, wait_until answers) end with a "(Docket state ...)" line: this session's branch, the pull request from it and its checks, the sessions under you still working or waiting on the user, and the number your next question to the user takes; a part left out means there is none. Trust it rather than checking again with git status, gh pr view, list_sessions or get_session_report. To wait for a pull request, its checks, a port or another session, call mcp__portal__wait_until once instead of sleeping and checking in a loop.
